# Спецификация листов дашборда v2 (только значения, без формул)

Источник данных — `http://89.108.66.36/export_stats` (CSV, 5 срезов через `UrlFetchApp`).
БД напрямую не используется. Сборка — Apps Script [`build_dashboard.gs`](./build_dashboard.gs).

**Принцип v2:** на листах **нет ни одной формулы**. Скрипт забирает CSV, считает все
показатели в JavaScript (проценты, воронку, статусы) и пишет готовые значения через
`setValue/setValues`. Поэтому `#ERROR!` из-за локали/разделителей и каскадных ссылок
на другие листы невозможны.

## Состав книги (порядок листов)

| # | Лист | Назначение | Видимость |
|---|------|------------|-----------|
| 1 | `Дашборд` | Всё, что смотрит владелец | виден |
| 2 | `Сырые данные` | `metric,value` — KPI за вчера | **скрыт** |
| 3 | `Функции` | `feature,yesterday,total` + отсортированный хелпер `D:E` | виден |
| 4 | `История` | `date,active_members,active_families,syncs,tasks_done,achievements` + скрытые хелперы `G:I` | виден |
| 5 | `Достижения` | `achievement_key,period,count` | виден |
| 6 | `Приложения` | `app,minutes_yesterday` + часы в `C` | виден |
| 7 | `_Служебный` | время/дата/статус обновления, диагностика | **скрыт** |

## Что пишется на листы данных (значения)

### `Сырые данные` (скрыт)
`A1:B1` — `metric,value`; строки 2–17: `date_measured` (текст, ISO), затем метрики числами:
`active_families_yesterday`, `active_members_yesterday`, `total_families`, `total_members`,
`total_accounts`, `new_families_yesterday`, `new_members_yesterday`, `new_accounts_yesterday`,
`syncs_yesterday`, `tasks_created_yesterday`, `tasks_done_yesterday`, `tasks_approved_yesterday`,
`achievements_yesterday`, `garden_changes_yesterday`, `rewards_requested_yesterday`.

### `Функции`
`A:C` — все 10 строк из CSV. Хелпер `D1:E8` — только продуктовые функции (без «Новые …»),
отсортированные по «вчера» по убыванию — это диапазон графика. **Без SORT/FILTER-формул:**
сортировка сделана в JS.

### `История`
`A:F` — все дни из `daily&days=90` (на графике — последние 30). Даты — текст с форматом `@`.
Скрытые `G:I`: `G2` — дней с данными, `H2` — tasks_done последнего дня, `I2` — последняя дата.

### `Достижения`
`A:C` — пока только заголовок (достижений ещё нет).

### `Приложения`
`A:B` — приложения и минуты за вчера; `C` — часы (число, считает JS). На «Дашборде» — топ-10.

### `_Служебный`
`A3/B3` — последнее обновление (МСК, текст), `A4/B4` — дата данных (текст `@`),
`A5/B5` — статус `OK` / ошибка, `A6/B6` — источник, `F2` — диагностика (в т.ч. ошибки графиков).

## Лист «Дашборд»: карта (v2)

| Строки | Что |
|---|---|
| 1 | Шапка «Good Family · продуктовая аналитика» |
| 2 | `Данные за <дата> (вчера, UTC) · обновлено: <время>` — строка целиком собирается в JS |
| 4–7 | KPI: `A6` активные семьи, `C6` активные пользователи, `E6` топ-функция, `G6` новые семьи; 5/7 — метка/подпись |
| 9–16 | «Хорошие дела, сад, достижения»: `Функция | Вчера | Всего | Комментарий` |
| 18–30 | Воронка и охват (11 метрик): семьи, активные, участники, среднее на семью, создано→выполнено→подтверждено, новые семьи/участники/аккаунты |
| 32–40 | **Качество данных**: 7 проверок (`ok`/`⚠`/`0`/`вкл.`) + условное форматирование |
| 42–53 | **Топ-10 приложений** за вчера (приложение, минуты, часы) |
| 55–57 | «Чего пока нет и почему» (retention/DAU-WAU/когорты — нет данных) + оговорка по top_apps |
| 59 | Заголовок «ГРАФИКИ» |

Графики (все диапазоны — на значениях, не формулы):
1. `A60` — «Активность: пользователи и семьи (до 30 дней)», линейный, `История!A:C`.
2. `E60` — «Функции за вчера (по убыванию)», горизонтальные столбцы, `Функции!D1:E8`.
3. `A75` — «Хорошие дела: создано → выполнено → подтверждено (всего)», столбцы, `A25:B27`.
4. `E75` — «Привлечение за вчера», столбцы, `A28:B30`.

Оформление: шапка `#1B5E20`, секции `#ECEFF1`, заголовки таблиц `#CFD8DC`,
чередование строк `#F7F9FA`, KPI-заливки (зелёная/синяя/янтарная/сиреневая),
числовые форматы `#,##0`, среднее на семью `0.00`, часы `0.0`.
Защита (с предупреждением): «Дашборд», «_Служебный». Скрыты: «Сырые данные», `_Служебный`, `История!G:I`.

## Про v1 и #ERROR! (для истории)
В v1 дашборд был на формулах (`IFERROR(VLOOKUP(...))`, `SORT/FILTER`, `ARRAYFORMULA`).
Владелец запустил v1 в книге с русской локалью: Google парсит формулы с разделителем `;`,
поэтому **все 50 формул с запятыми** получили `#ERROR!` (уцелела одна без разделителей —
`=COUNTA(...)`). Разбор всех 51 ячейки: `raw/export_error_table.md`.
v2 устраняет причину: формул нет. Ручной режим IMPORTDATA из первой версии ТЗ больше не нужен.

## Проверка после запуска (для аналитика)
- На листах нет ни одной ячейки, начинающейся с `=` (кроме текста подписей).
- `_Служебный!B4` = ISO-дата (`2026-11-08`), `B3` = время, `B5` = `OK`.
- Блок «Качество данных»: все проверки `ok`/`0`/`вкл.` (⚠ быть не должно после фиксов сервера).
- 4 графика на месте; при проблеме — причина в `_Служебный!F2`.
