# Спецификация листов дашборда (что и где лежит)

Источник данных — `http://89.108.66.36/export_stats` (CSV). Единственный источник, БД напрямую
не используется. Основной способ сборки — Apps Script [`build_dashboard.gs`](./build_dashboard.gs)
(он создаёт всё описанное ниже автоматически). Этот документ — карта листов и формул:
по нему можно собрать дашборд вручную или проверить, что скрипт сделал.

## Состав книги (порядок листов)

| # | Лист | Назначение | Видимость |
|---|------|------------|-----------|
| 1 | `Дашборд` | Всё, что смотрит владелец | виден |
| 2 | `Сырые данные` | `metric,value` — KPI за вчера | **скрыт** |
| 3 | `Функции` | `feature,yesterday,total` + отсортированный хелпер | виден |
| 4 | `История` | `date,active_members,active_families,syncs,tasks_done,achievements` | виден |
| 5 | `Достижения` | `achievement_key,period,count` | виден |
| 6 | `Приложения` | `app,minutes_yesterday` (недостоверно — см. предупреждение) | виден |
| 7 | `_Служебный` | время обновления, дата данных, статус, (опц.) URL для IMPORTDATA | **скрыт** |

Правила:
- листы 2–6 заполняются из экспорта; вручную не редактируются;
- на `Дашборде` — только формулы; вручную не редактируется;
- лист `_Служебный` защищён (предупреждение при правке) и скрыт.

## Листы данных (после обновления)

### `Сырые данные` (скрыт)
`A1` = CSV `table=summary`, колонки `metric,value`. Строки (порядок сохраняется сервером):
`date_measured`, `active_families_yesterday`, `active_members_yesterday`, `total_families`,
`total_members`, `total_accounts`, `new_families_yesterday`, `new_members_yesterday`,
`new_accounts_yesterday`, `syncs_yesterday`, `tasks_created_yesterday`, `tasks_done_yesterday`,
`tasks_approved_yesterday`, `achievements_yesterday`, `garden_changes_yesterday`,
`rewards_requested_yesterday`.

### `Функции`
`A1` = CSV `table=features`: `feature,yesterday,total` (10 строк + заголовок).
Хелпер (заполняется скриптом):
- `D1:E1` — заголовки «Функция (по популярности)», «Вчера»;
- `D2` — `=IFERROR(SORT(FILTER($A$2:$B$100,$A$2:$A$100<>"",LEFT($A$2:$A$100,5)<>"Новые"),2,FALSE),"")`
  — только продуктовые функции (без строк «Новые …»), по убыванию за вчера.

### `История`
`A1` = CSV `table=daily&days=90` (на графике показываем последние 30 строк).
Служебные скрытые колонки `G:I`:
- `G2` `=COUNTA($A$2:$A$1000)` — дней с данными;
- `H2` `=IFERROR(INDEX($E$2:$E$1000,COUNTA($A$2:$A$1000)),"")` — tasks_done последнего дня;
- `I2` `=IFERROR(INDEX($A$2:$A$1000,COUNTA($A$2:$A$1000)),"")` — последняя дата.

### `Достижения`
`A1` = CSV `table=achievements`; сейчас только заголовок (достижений ещё нет).

### `Приложения`
`A1` = CSV `table=top_apps`; `C` — хелпер «Часы (суммарно)»:
`=ARRAYFORMULA(IF($B$2:$B$100="","",ROUND($B$2:$B$100/60,1)))`.
**Важно:** на «Дашборд» этот лист не выводится. Минуты накапливаются клиентом
(у отдельных устройств до 160 ч/сутки) — до фикса приложения это не аналитика.

### `_Служебный`
- `B3` — «последнее обновление (МСК)» (пишет скрипт);
- `B4` — `=IFERROR(VLOOKUP("date_measured",'Сырые данные'!A:B,2,FALSE),"нет данных")`;
- `B5` — статус `OK` / текст ошибки;
- `B6` — источник без секрета;
- `B9:B13` — (опционально) полные URL с секретом для ручного режима IMPORTDATA;
- `F2` — диагностика последней ошибки.

## Лист «Дашборд»: карта ячеек

### Шапка
| Ячейка | Содержимое |
|---|---|
| `A1:H1` | `Good Family · продуктовая аналитика` (тёмно-зелёная плашка) |
| `A2:H2` | `="Данные за "&_Служебный!B4&" (вчера, UTC) · обновлено: "&_Служебный!B3&IF(_Служебный!B5="OK",""," · ⚠ "&_Служебный!B5)` |

### Блок A. KPI за вчера (строки 4–7)
Заголовок `A4:H4` — «КЛЮЧЕВЫЕ KPI ЗА ВЧЕРА». Карточки: строки 5–7, пары столбцов
`A:B | C:D | E:F | G:H` (метка / значение / подпись).

| Ячейка значения | Формула | Подпись |
|---|---|---|
| `A6` | `=IFERROR(VLOOKUP("active_families_yesterday",'Сырые данные'!$A:$B,2,FALSE),"нет данных")` | «из N семей · % активны» |
| `C6` | `=IFERROR(VLOOKUP("active_members_yesterday",'Сырые данные'!$A:$B,2,FALSE),"нет данных")` | «всего участников: N» |
| `E6` | `=IFERROR(INDEX('Функции'!$D$2:$D$8,1),"нет данных")` | «событий за вчера: N» |
| `G6` | `=IFERROR(VLOOKUP("new_families_yesterday",'Сырые данные'!$A:$B,2,FALSE),"нет данных")` | «новых участников: N · аккаунтов: N» |

### Блок B. Хорошие дела, сад, достижения (строки 9–16)
`A10:D10` — заголовки «Функция | Вчера | Всего | Комментарий».
Строки 11–16: `A` — метка (точное имя из листа «Функции»), `B`/`C` —
`=IFERROR(VLOOKUP($A11,'Функции'!$A:$C,2,FALSE),"")` и `…,3,…` (вчера / всего).
Метки: `Хорошие дела: создано`, `Хорошие дела: выполнено ребёнком`,
`Хорошие дела: подтверждено родителем`, `Достижения: получено`,
`Семейный сад: изменения`, `Награды: запрошено`.

### Блок C. Воронка и охват (строки 18–30)
`A19` — «Метрика», `B19` — «Значение», `C19` — «Комментарий».

| Строка | Метрика | Формула B | Комментарий C |
|---|---|---|---|
| 20 | Семей всего | `VLOOKUP("total_families",…)` | |
| 21 | Активные семьи вчера | `VLOOKUP("active_families_yesterday",…)` | `=TEXT(B21/B20,"0%")&" семей были активны"` |
| 22 | Участников всего | `VLOOKUP("total_members",…)` | |
| 23 | Активные пользователи вчера | `VLOOKUP("active_members_yesterday",…)` | `=IF(B23>B22,"⚠ активных больше, чем участников","ok")` |
| 24 | Участников на семью (сред.) | `=ROUND(B22/B20,2)` | в среднем на семью |
| 25 | Хорошие дела: создано (всего) | `=C11` | |
| 26 | Хорошие дела: выполнено (всего) | `=C12` | `=TEXT(B26/B25,"0%")&" от созданных"` |
| 27 | Хорошие дела: подтверждено (всего) | `=C13` | `=TEXT(B27/B26,"0%")&" от выполненных"` |
| 28 | Новые семьи вчера | `VLOOKUP("new_families_yesterday",…)` | |
| 29 | Новые участники вчера | `VLOOKUP("new_members_yesterday",…)` | |
| 30 | Новые аккаунты вчера | `VLOOKUP("new_accounts_yesterday",…)` | аккаунты = пользователи сервера (`users`) |

### Блок D. Качество данных (строки 32–40)
`A33:C33` — заголовки «Проверка | Статус | Пояснение». Строки 34–40 — 7 проверок:
дней истории; задания вчера (история vs summary); активные пользователи vs всего;
`syncs` vs активные; достижения; сад; топ приложений (скрыт до фикса клиента).
Условное форматирование `B34:B40`: `⚠` → красный фон, `ok` → зелёный текст.

### Блок E. Ограничения (строки 42–44)
Две плашки мелким серым текстом: чего нет в экспорте (retention/DAU-WAU/когорты/воронка
«семья→приглашение→задача») и почему не выводим топ приложений.

### Графики (якоря)
| График | Диапазон | Тип | Позиция |
|---|---|---|---|
| Активность: пользователи и семьи (до 30 дней) | `'История'!A..C` (последние 30 строк) | линейный | `A47` (470×290) |

## Оформление (что задаёт скрипт)
- Шапка `#1B5E20` + белый текст; секции `#ECEFF1`; заголовки таблиц `#CFD8DC`;
  строки через одну `#F7F9FA`; тонкие границы `#CFD8DC`.
- KPI-карточки: зелёная / синяя / янтарная / сиреневая заливки; число 26 pt.
- Числовые форматы: `#,##0`; среднее участников — `0.00`.
- Скрыты: `Сырые данные`, `_Служебный`, служебные колонки `G:I` на «Истории».
- Защита от правок (с предупреждением): `Дашборд`, `_Служебный`.

## Ручной режим (IMPORTDATA), если скрипт запускать не хотят
1. Вставить URL с секретом в `_Служебный!B9:B13`:
   - `B9` summary, `B10` features, `B11` `…&table=daily&days=90`,
     `B12` achievements, `B13` top_apps (в каждом — `…&format=csv&table=…`).
2. В ячейки `A1` листов данных вставить (английские имена функций, аргументы через `,`):
   - `Сырые данные!A1` → `=IMPORTDATA(_Служебный!B9)`
   - `Функции!A1` → `=IMPORTDATA(_Служебный!B10)`
   - `История!A1` → `=IMPORTDATA(_Служебный!B11)`
   - `Достижения!A1` → `=IMPORTDATA(_Служебный!B12)`
   - `Приложения!A1` → `=IMPORTDATA(_Служебный!B13)`
3. Остальные ячейки «Дашборда» и хелперы `Функции!D2`, `История!G2:I2`,
   `Приложения!C2` — из этой же спецификации.
4. `IMPORTDATA` обновляется сама ~раз в час. Секрет при этом лежит на скрытом листе —
   это допустимо, но менее безопасно, чем Script Properties из скрипта.
   Примечание: в русской локали таблицы формулы могут требовать `;` вместо `,`;
   надёжнее запустить скрипт, он ставит формулы сам в машинном синтаксисе.

## Соответствие ТЗ
- 3 обязательных KPI (семьи, пользователи, топ-функция) — блок A;
- функции «хорошие дела / сад / достижения» — блок B + график функций;
- динамика 30 дней — график 1 (сейчас 1 точка: история с 07.11.2026);
- воронка — блок C + график 3;
- топ приложений — лист «Приложения» с предупреждением (осознанно не на дашборде);
- секрет не на лицевых листах; скрытый/защищённый лист — `_Служебный`;
- автообновление — триггер `refreshDashboard` раз в час.
