## Что осталось / на что смотреть

1. **`total_accounts` (6) ≠ `total_members` (12)**: «аккаунты» — это таблица `users`
   (регистрации/подтверждения), «участники» — `members` (семья). В дашборде подписаны
   раздельно; при выводах не смешивать.
2. **`features` смешивает продукт и привлечение**: строки «Новые семьи/участники/аккаунты»
   — не функции. На дашборде функции отфильтрованы от acquisition-событий (в JS).
3. **Смысл `syncs`** — число строк `screen_time` за день (уникальность `user_id+date`),
   то есть «человеко-дней с синком», а не число событий синхронизации. Сейчас совпадает
   с активными пользователями.
4. **Retention/DAU-WAU/когорты** по этому экспорту не считаются: только суточные агрегаты
   без привязки к пользователю. Для них нужен отдельный серверный срез (не делали).
5. **HTTP и секрет в query-строке**: для Google-импорта ок, но в логах прокси секрет виден;
   в дашборде он хранится только в Script Properties.
6. `format=json` у эндпоинта игнорирует `table` и отдаёт один общий JSON; неизвестный
   `table` в CSV-режиме молча отдаёт `summary`. Для дашборда не критично (используются 5 CSV).

## Почему v1 на формулах был обречён (контекст для истории)

Книга владельца — русская локаль (разделитель аргументов `;`). Формулы, записанные скриптом
в en-US синтаксисе (`,`), Google не распарсил: 50 из 50 формул с запятыми → `#ERROR!`,
уцелела единственная без разделителей — `=COUNTA(...)`. Это не проблема функций
(VLOOKUP/IFERROR/SORT сами по себе рабочие) и не экспорт в Excel. Вывод: в этой книге
формулы писать нельзя, поэтому v2 — только значения. Полный разбор 51 ячейки:
[`raw/export_error_table.md`](./raw/export_error_table.md).
